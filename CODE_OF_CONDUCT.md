# Code of Conduct

## Our Commitment

We are committed to providing a welcoming, respectful, and professional
environment for everyone who participates in this project.

Contributors, maintainers, reviewers, issue reporters, and other participants
are expected to interact constructively and in good faith.

## Expected Behavior

Participants are expected to:

- Be respectful and professional.
- Assume good intent while remaining open to correction.
- Provide constructive technical feedback.
- Focus discussions on the technical problem or contribution.
- Respect different backgrounds, experiences, and viewpoints.
- Accept reasonable correction and feedback.
- Protect confidential and security-sensitive information.
- Follow the project's security reporting process when reporting
  vulnerabilities.

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, discrimination, intimidation, or personal attacks.
- Threats or deliberately hostile behavior.
- Trolling or intentionally disruptive conduct.
- Publishing private or sensitive information without permission.
- Sharing credentials, secrets, private keys, or other sensitive security
  material.
- Deliberately compromising project infrastructure or services.
- Attempting to exploit security vulnerabilities outside the project's
  responsible disclosure process.
- Unwelcome sexual or personal attention.
- Other conduct that would reasonably make participation unsafe or hostile.

## Security-Related Conduct

Security research and vulnerability reporting are welcome when performed
responsibly.

Security vulnerabilities should be reported according to `SECURITY.md`
rather than through public issues, pull requests, or discussions.

Do not:

- Access data that does not belong to you.
- Disrupt project infrastructure.
- Destroy or modify data unnecessarily.
- Publish credentials or secrets.
- Publicly disclose exploitable vulnerabilities before reasonable
  remediation coordination.

## Maintainer Responsibilities

Project maintainers are responsible for:

- Maintaining a professional and respectful project environment.
- Reviewing reported conduct concerns.
- Taking appropriate and proportionate action when this Code of Conduct is
  violated.
- Protecting confidential information provided during private reports.

## Enforcement

If you experience or witness unacceptable behavior, report it privately to
the project maintainers.

Security vulnerabilities must be reported according to `SECURITY.md`.

Maintainers may take appropriate action in response to violations, including
warnings, removal of inappropriate content, temporary restrictions, or
removal from project participation.

## Scope

This Code of Conduct applies to project spaces and activities associated
with the repository, including:

- GitHub issues.
- Pull requests.
- Discussions.
- Code reviews.
- Project-maintained communication channels.
- Other activities conducted on behalf of the project.

## Good-Faith Participation

Technical disagreement is expected in an engineering project.

Strong technical opinions are welcome when expressed respectfully and
supported by relevant evidence. Disagreement about implementation, design,
security controls, or project direction is not by itself a violation of this
Code of Conduct.

## Attribution

This Code of Conduct is based on principles commonly used by open-source
projects and is intended to establish project-specific expectations for
respectful participation.
